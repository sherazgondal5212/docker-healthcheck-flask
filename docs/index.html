Project 1.1: Containerized Flask App

A Flask API packaged with Docker, served by Gunicorn and run as a non-root user. Built and tested in AWS CloudShell, then published to GitHub.

Architecture diagram

One container on one Docker host. Port 5000 is published to the host.

Technical workflow

  1. Wrote a small Flask app with / and /health routes, and pinned its dependencies.
  2. Wrote a Dockerfile on python:3.12-slim that installs dependencies first, so Docker can cache that layer.
  3. Created an appuser account and switched to it before the app starts.
  4. Replaced the Flask dev server with Gunicorn as the process that serves traffic.
  5. Built the image, started the container with -p 5000:5000, and tested both endpoints.
  6. Checked logs and the running user, then removed the container and published the project to GitHub.

Automation scripts breakdown

FileWhat it does
app/app.pyDefines the / route (reads APP_VERSION from the environment) and the /health route.
app/requirements.txtPins Flask 3.0.3 and Gunicorn 22.0.0 so builds are repeatable.
DockerfileBuilds from python:3.12-slim, installs dependencies, creates appuser, and starts Gunicorn on port 5000.
.dockerignoreKeeps .git, caches and .env out of the build context.
Build and run
docker build -t gda-flask:1.0 .
docker run -d --name flask-test -p 5000:5000 -e APP_VERSION=1.0 gda-flask:1.0
